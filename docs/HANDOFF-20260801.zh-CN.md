## 机器环境与两个关键缺陷（重要）

本机 ROCm torch 构建 `2.10.0+git8514f05` 有两个缺陷：

1. **CPU 端无 LAPACK**：`torch.linalg.eigh/eigvalsh/svd/lu_factor` 在 CPU 张量上直接抛
   `RuntimeError: ... requires compiling PyTorch with LAPACK`。GPU（rocSOLVER）正常。
   冻结代码 `run_p4_diagnostic.py:_gram_condition_numbers` 把 Gram 矩阵显式 `.detach().cpu()`
   后求 `eigvalsh` → 每个 run 在 monitor step 50 崩溃，早于首次 checkpoint（step 100），
   因此首轮 0 个 checkpoint 产出。
2. **强制退出码 0**：任何 `import torch` 的进程在解释器退出时（`SystemExit` 或未捕获异常）
   一律以退出码 0 结束（疑似 torch 注册的 shutdown 钩子）。实证：
   `import torch; raise SystemExit(2)` → exit 0；`import torch; os._exit(2)` → exit 2。
   → executor 依赖子进程退出码做门控，故首轮误报 `PROMOTION_GO`；pytest 有失败却退出 0 也是此因。

**结论：本机任何"退出码=0"的门控信号都不可信，须以 `summary.json`/`diagnostic_gate.json`/`failure.json` 为准。**
